# الأدوار والصلاحيات

## AUTH01 تسجيل الدخول

الحسابات ينشئها المدير؛ لا يوجد تسجيل عام. البريد الإلكتروني فريد، وكلمة المرور مؤكدة عند الإنشاء. تسجيل الدخول والخروج واستعادة كلمة المرور عبر رابط محدود الصلاحية. تعطيل حساب يمنع دخوله ويلغي جلساته. منع تعطيل أو إزالة صلاحية آخر مدير فعال.

## مدير النظام

إدارة جميع الوحدات والمستخدمين والأدوار والعملات، تأكيد وإلغاء الطلبات، استلام المشتريات وتسليم الطلبات، التسويات، مراجعة وتسجيل وعكس التحصيل، والتقارير والتدقيق.

## موظف المبيعات

إدارة العملاء، قراءة المنتجات والكميات المتاحة، إنشاء وتعديل المسودات وتأكيد وإلغاء الطلبات غير المسلمة وغير المحصلة، وتسجيل التحصيل وقراءة دفعات العملاء. لا يعدل المخزون أو العملات أو أسعار شراء المنتجات أو المستخدمين. يرى تقرير المبيعات والتحصيل فقط، ولا يرى قيمة المخزون.

## أمين المخزن

قراءة المنتجات والموردين، إنشاء مشتريات وتعديل مسوداتها واستلامها، تسليم الطلبات المؤكدة، قراءة الحركات والكميات وإنشاء مسودة جرد. اعتماد الجرد للمدير. لا يسجل التحصيل ولا يدير أسعار الصرف أو المستخدمين. الأسعار المالية مخفية من شاشاته حيث لا تلزم الاستلام.

## AUTH02 قواعد مشتركة

- كل قائمة وتفاصيل وإجراء وتصدير تحميه صلاحية مستقلة على السيرفر؛ إخفاء الزر وحده غير كاف.

- الطلبات والدفعات تبقى محفوظة عند تعطيل الموظف؛ المستخدم المرتبط بعمليات يعطل ولا يحذف.

- صفحة الملف الشخصي لتغيير الاسم وكلمة المرور واللغة؛ اللغة تحفظ لكل مستخدم.

- رفض غير المصرح له برسالة واضحة دون تسريب معلومات المستند.

## معايير القبول

- AC01 أمين المخزن لا يستطيع إرسال طلب HTTP مباشر لتسجيل دفعة.

- AC02 الحساب المعطل يفقد جلساته ولا يستطيع الدخول مجددًا.

- AC03 المبيعات لا ترى تكلفة المخزون في الصفحة أو التصدير أو استجابة السيرفر.

# البيانات الأساسية والترجمة

## CAT01 المنتجات والفئات

المنتج: SKU فريد غير قابل للتغيير بعد أول حركة، اسم عربي وإنجليزي مطلوبان، فئة، وحدة ثابتة قطعة، سعر بيع مرجعي بالعملة الأساسية، حد تنبيه صحيح غير سالب، وحالة فعال أو غير فعال. الفئة لها اسمان عربي وإنجليزي. لا حذف لمنتج مرتبط بمستند؛ التعطيل يمنع استخدامه في مستند جديد ويسمح بإكمال مستنداته المؤكدة.

السعر المرجعي يساعد الإدخال فقط؛ سعر البيع النهائي يحفظ على بند الطلب. القيم المالية غير سالبة والكمية عدد صحيح موجب. لا يوجد إدخال مباشر لكمية المنتج؛ الرصيد الافتتاحي يسجل كتسوية مع سبب.

## CRM01 العملاء والموردون

لكل طرف اسم تجاري مطلوب، كود فريد مولد، هاتف، بريد اختياري بصيغة صحيحة، عنوان، وحالة. أسماء الأطراف لا تترجم. منع حذف طرف مرتبط بمستند. شاشة العميل تعرض طلباته ودفعاته والمتبقي حسب كل عملة دون جمع عملات مختلفة مباشرة. المورد يعرض مستندات مشترياته؛ حسابات سداد الموردين مؤجلة.

## L10N01 اللغات

عربي RTL وإنجليزي LTR مع زر تبديل ظاهر. العربية تستخدم Noto Sans Arabic والإنجليزية Inter. ترجمة القوائم والفورمات والرسائل والبريد وعناوين التصدير. قيم SKU والأرقام المرجعية والبريد تبقى LTR داخل RTL. عرض العملة بكودها ISO لمنع التباس رمز الدولار. أسماء المنتجات تظهر بلغة المستخدم، وباللغة الأخرى كبديل إن غاب نص قديم.

## UX01 سلوك القوائم

بحث مؤخر قصيرًا مع Pagination على السيرفر، وفرز وحفظ الفلاتر في رابط الصفحة. افتراضي 20 صفًا، واختيارات 20 و50 و100. عرض عدد النتائج وحالة فارغة وزر إعادة ضبط. تأكيد قبل أي إجراء مؤثر؛ تعطيل زر الحفظ أثناء الإرسال مع إبقاء مدخلات المستخدم بعد الخطأ.

## معايير القبول

- AC04 تكرار SKU مرفوض حتى مع طلبين متزامنين.

- AC05 تغيير اللغة يعكس التخطيط ويحافظ على الصفحة والفلاتر.

- AC06 تعديل اسم المنتج أو سعره لا يغير بيانات المستندات المؤكدة القديمة.

# طلبات البيع والتحصيل

## SO01 إنشاء المسودة

الحقول: رقم فريد مولد، عميل فعال، تاريخ، عملة، سعر صرف، ملاحظات، وبنود تحتوي المنتج والكمية وسعر الوحدة. يمنع تكرار المنتج في نفس المستند. الإجمالي مجموع البنود، دون ضرائب أو خصومات في النسخة الأولى. المسودة قابلة للتعديل والحذف ولا تحجز مخزونًا. تعرض معاينة سعر الصرف والتقييم الأساسي بوضوح.

## SO02 دورة الحالات

Draft → Confirmed → Delivered. يسمح بالإلغاء من Draft أو Confirmed فقط إذا لم توجد دفعات فعالة. التأكيد يحجز كامل الكميات المتاحة داخل Transaction واحدة، ويثبت العملة وسعر الصرف والبنود وأسماء المنتجات وبيانات العميل. لا تعديل مالي بعد التأكيد. الإلغاء يفك الحجز، والتسليم يخصم الموجود والمحجوز بنفس الكمية. لا تسليم أو إلغاء ثانٍ لنفس المستند.

التسليم الكامل فقط. عند نقص أي بند، تفشل عملية التأكيد بالكامل ويظهر المنتج والمتاح والمطلوب. لا يسمح بمخزون سالب أو حجز جزئي صامت. الطلب المسلم لا يلغى؛ المرتجعات مرحلة لاحقة.

## PAY01 التحصيل

يسمح بتسجيل دفعة على Confirmed أو Delivered فقط، وبنفس عملة الطلب. الحقول: المبلغ، التاريخ، الطريقة Cash أو Bank transfer، مرجع اختياري وملاحظة. مجموع الدفعات الفعالة لا يتجاوز الإجمالي؛ الحالة المالية Unpaid أو Partially paid أو Paid مستقلة عن حالة الطلب. المتبقي = الإجمالي − صافي الدفعات الفعالة.

الدفعة المنشورة لا تعدل ولا تحذف. المدير يستطيع عكسها مرة واحدة بسبب إلزامي، مع الاحتفاظ بالدفعة الأصلية ومرجع العكس في التدقيق. لا عكس بمبلغ جزئي. بعد عكس جميع الدفعات يمكن إلغاء طلب مؤكد. يسجل التحصيل قيمة أساسية بسعر صرف الطلب لتقارير التشغيل فقط.

## معايير القبول

- AC07 موجود 10 ومحجوز 0، يتزامن طلبان كل منهما 7: يؤكد واحد فقط ويصبح المتاح 3.

- AC08 فشل حجز بند يعيد جميع تغييرات الطلب ولا يترك حجزًا لبعض البنود.

- AC09 إرسال التسليم أو الدفعة مرتين بالمفتاح نفسه ينشئ أثرًا واحدًا فقط.

- AC10 دفعتان متزامنتان لا تتجاوزان المتبقي؛ قفل الطلب أثناء التحقق والتسجيل.

# المشتريات والمخزون والجرد

## PO01 المشتريات

مستند شراء بحالات Draft → Received أو Draft → Cancelled. المورد والتاريخ والعملة وسعر الصرف والبنود مطلوبة. تكلفة الوحدة بعملة المستند. الاستلام الكامل ينشر كل البنود في Transaction واحدة ويثبت البيانات ويزيد الموجود، ولا يغير المحجوز. المستند المستلم غير قابل للتعديل أو الإلغاء. لا إدارة دفعات موردين في النسخة الأولى.

## INV01 رصيد المخزون

لكل منتج في المخزن سجل واحد: on_hand للموجود وreserved للمحجوز؛ available = on_hand − reserved. دائمًا on_hand ≥ reserved ≥ 0. قفل سجلات المنتجات بترتيب ID ثابت في التأكيد والاستلام والتسليم والجرد لتقليل التعارض. قاعدة البيانات تمنع تكرار سجل رصيد المنتج.

حركات append-only: opening، purchase_receipt، sales_reserve، sales_release، sales_delivery، adjustment. كل حركة تحفظ المنتج ونوعها وتغير الموجود وتغير المحجوز والرصيد بعد الحركة ومرجع المصدر والمنفذ والوقت. لا تعديل أو حذف من الواجهة. منع نشر نفس مصدر الحركة مرتين بقيد فريد مناسب.

## INV02 تكلفة المخزون

تقييم تشغيلي بمتوسط التكلفة المرجح المتحرك بالعملة الأساسية. بعد الاستلام: المتوسط الجديد = (الموجود القديم × المتوسط القديم + تكلفة الوارد الأساسية) ÷ (الموجود القديم + الوارد). إذا كان الموجود صفرًا، المتوسط يساوي تكلفة الوارد. التسليم يحفظ متوسط التكلفة وقت التسليم كبصمة تكلفة للبند ويخفض القيمة بذلك. لا تقرير أرباح محاسبي في النسخة الأولى.

## INV03 الجرد والتسويات

أمين المخزن ينشئ مسودة تحتوي المنتجات والكمية المعدودة والرصيد المتوقع ورقم إصدار الرصيد. المدير يعتمد بعد مراجعة الفرق والسبب. إذا تغير الرصيد منذ العد يرفض الاعتماد ويطلب تحديث العد؛ لا يعتمد على بيانات قديمة. الكمية المعدودة لا تقل عن المحجوز. التسوية الموجبة تستخدم المتوسط الحالي؛ عند رصيد صفر تلزم تكلفة أساسية صريحة. السالبة تستخدم المتوسط الحالي. لا تعديل بعد الاعتماد.

## معايير القبول

- AC11 تأكيد 4 من موجود 10 يعطي محجوز 4 ومتاح 6؛ التسليم يعطي موجود 6 ومحجوز 0.

- AC12 استلام 10 بتكلفة 20 بعد 10 بتكلفة 10 يعطي متوسطًا 15 قبل أي تسليم.

- AC13 جرد قديم أو كمية معدودة أقل من المحجوز يرفض دون أي تغيير.

# العملات والدقة المالية

## FX01 إعداد العملات

المدير يدير كود ISO فريدًا، الاسم، عدد المنازل العشرية، والحالة. العملات التجريبية EGP وUSD وSAR بمنازل عرض 2. العملة الأساسية EGP وسعرها 1، وتثبت بعد أول مستند مؤكد أو حركة مالية. لا تعطيل عملة توجد بها مسودات أو مستندات مفتوحة حتى تسويتها. المستندات القديمة تظل قابلة للقراءة.

## FX02 اتجاه التحويل

اتجاه السعر ثابت: وحدة واحدة من عملة المستند = X من العملة الأساسية. مثال تعليمي USD 1 = EGP 50. طلب USD 100 = EGP 5000. يظهر الاتجاه مكتوبًا بجوار الحقل، ولا يعرض رقمًا مبهمًا. عند تحويل السعر المرجعي للعرض في الطلب: السعر الأساسي ÷ سعر الصرف، ثم يراجع الموظف سعر البند.

شاشة الأسعار تحفظ العملة والسعر الموجب وتاريخ السريان والمنفذ. يستخدم المستند أحدث سعر يسري في تاريخه؛ إذا لم يوجد يمنع التأكيد. ينسخ السعر إلى المسودة، ويعاد التحقق عند التأكيد؛ إذا تغير السعر المعتمد يظهر التغيير ويطلب مراجعة المستخدم قبل التأكيد. لا تعديل لسعر صرف مستند مؤكد؛ تغيير جداول الأسعار يؤثر على المستندات الجديدة فقط.

## FX03 الحساب والتقريب

استخدم DECIMAL أو مكتبة أعداد عشرية، دون float للحسابات المالية. مقترح: المبالغ DECIMAL(20,2)، أسعار الصرف DECIMAL(20,8)، ومتوسط التكلفة DECIMAL(24,8). إجمالي البند = تقريب HALF_UP للكمية × سعر الوحدة إلى منزلتين؛ إجمالي المستند مجموع البنود المقربة. الإجمالي الأساسي = تقريب إجمالي المستند × سعر الصرف إلى منزلتين. تحفظ تكلفة الوارد الدقيقة حتى 8 منازل لاستخدام المتوسط.

تحدد حدود الإدخال قبل التنفيذ لمنع تجاوز سعة الأعمدة، مثل كمية حتى مليون وسعر وحدة حتى مليون، مع رفض مستند يتجاوز الحد المالي المتفق عليه. التقارير تجمع القيم الأساسية المحفوظة، ولا تعيد تقييم التاريخ بسعر اليوم. عرض USD وSAR وEGP مع المبالغ؛ لا جمع خام للعملات المختلفة.

## معايير القبول

- AC14 تغيير الدولار من 50 إلى 55 لا يغير طلبًا مؤكدًا بقيمة USD 100 وتقييم EGP 5000.

- AC15 سعر صفر أو سالب أو مفقود يمنع التأكيد والاستلام.

- AC16 التحصيل بعملة مختلفة أو بقيمة أعلى من المتبقي مرفوض.

- AC17 اختبار حالات الكسور والتقريب والحدود المالية على السيرفر.

# التقارير والمتطلبات المشتركة

## REP01 الداشبورد والتقارير

الداشبورد: قيمة الطلبات المسلمة خلال الفترة بالعملة الأساسية، التحصيل الصافي خلال الفترة بسعر الطلب، المتبقي على الطلبات المؤكدة والمسلمة، عدد الطلبات المؤكدة، وتنبيهات المنتجات التي متاحها ≤ حد التنبيه. لا تعتبر المسودات أو الملغاة مبيعات. لا تخلط تاريخ التسليم وتاريخ الدفعة؛ يكتب أساس الفترة على كل مؤشر.

تقارير مستقلة: المبيعات حسب تاريخ التسليم والعميل والمنتج، التحصيل حسب تاريخ الدفعة والطريقة مع العكس، أرصدة المخزون الحالية، حركات المنتج بفترة ومرجع، والطلبات المستحقة حسب العميل والعملة مع قيمة أساسية. تقييم المخزون الحالي للمدير فقط. لا تقرير مخزون تاريخي قبل تصميم أرصدة تاريخية.

## REP02 التصدير

CSV يلتزم بنفس الصلاحيات والفلاتر والأعمدة الظاهرة، بترميز UTF-8، ويعرض العملة واتجاه سعر الصرف. تحييد خلايا النص التي تبدأ بـ = أو + أو - أو @ لمنع تنفيذها كصيغ عند فتح الملف. تصدير كبير يجهز كـ Job ويخطر المستخدم برابط تنزيل محمي ومحدود الصلاحية.

## NFR01 السلامة والاعتمادية

- Session authentication مع CSRF وRate limiting للدخول؛ التحقق من المدخلات والصلاحيات في كل إجراء.

- Idempotency key لإجراءات النشر والتحصيل مع قيد فريد؛ إعادة نفس المفتاح ببيانات مختلفة ترفض.

- إعادة المحاولة المحدودة عند Deadlock؛ رسائل تعارض واضحة ولا إرسال إشعارات قبل نجاح Commit.

- سجل تدقيق للفاعل والإجراء والمرجع والتاريخ وسبب الإلغاء أو العكس؛ لا تخزين كلمات مرور أو أسرار.

- تخزين الأوقات UTC وعرضها بتوقيت الشركة Africa/Cairo؛ حدود فلاتر التاريخ تحول إلى UTC.

- فهرسة الحقول المرتبطة بالفلاتر الفعلية؛ Eager loading وPagination لتجنب N+1.

## NFR02 تجربة الاستخدام

تصميم 1440px للكمبيوتر، و768px للتابلت، و390px للموبايل. القائمة الجانبية تصبح درجًا، والكروت تتكدس، والجداول تتحول لكروت مختصرة مع رابط تفاصيل. جداول البنود الواسعة داخل حاوية تمرير أفقي دون تمديد الصفحة. Labels ظاهرة، تركيز لوحة مفاتيح، ورسالة خطأ ملاصقة للحقل؛ الحالات لا تعتمد على اللون وحده.

## تقسيم المسؤوليات في Laravel

Controllers قصيرة، Form Requests للتحقق، Policies للصلاحيات، وServices أو Actions لعمليات التأكيد والتسليم والاستلام والتحصيل. لا يلزم Repository فوق كل Model. أضف Interfaces عند وجود بديل فعلي مثل مزود إشعارات أو أسعار صرف لاحقًا. Events وListeners بعد Commit للإشعارات؛ Jobs للتصدير والبريد؛ Scheduler لفحص انخفاض المخزون ومنع إرسال التنبيه نفسه كل مرة.

## أمثلة الاختبارات المطلوبة

Feature tests للصلاحيات ودورة المستندات؛ Integration tests على MySQL/MariaDB الفعلي للمعاملات والأقفال والقيود؛ Unit tests للحساب والتقريب. لا تعتبر SQLite دليلًا على صحة lockForUpdate. اختبر التزامن باتصالين مستقلين وقاعدة بيانات اختبار منفصلة.
